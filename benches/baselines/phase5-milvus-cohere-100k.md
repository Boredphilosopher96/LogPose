# Phase 5 Milvus Comparison: cohere-100k

Generated by `scripts/bench-milvus.sh`; do not edit by hand. See `benches/baselines/README.md` for how to read it.

**Synthetic data.** 100,000 vectors of 768 dimensions and 1,000 queries, cosine metric, from the embedding-like generator (32 latent dimensions, 256 clusters, seed 42). It mirrors only the shape of VectorDBBench Cohere 100K (768 dims, cosine); the public VectorDBBench files were not reachable.

Recall is mean recall@10 against exact ground truth. Each system's `ef` is the smallest swept value with recall of at least 0.95.

## Notes

- LogPose: recall is mean recall@k against exact ground truth computed by logpose-bench vdb-prepare
- LogPose: latency is measured by the client around each gRPC call, so it includes serialization and loopback transport
- LogPose: each concurrent client has its own gRPC connection and runs in the driver's tokio runtime on the same machine as the server
- LogPose: LogPose applies ef as max(ef, 4 * k) and widens it for filtered walks that come up short
- LogPose: the dataset is synthetic (embedding-like, see dataset.generator); it mirrors only the shape of the public dataset named in dataset.mirrors
- Milvus: recall is mean recall@k against exact ground truth computed by logpose-bench vdb-prepare
- Milvus: latency is measured by the client around each pymilvus search call, so it includes Python serialization and loopback transport
- Milvus: each concurrent client is its own Python process with its own connection, on the same machine as the server
- Milvus: searches use the collection's default consistency level; the scalar field has a STL_SORT index
- Milvus: the dataset is synthetic (embedding-like, see dataset.generator); it mirrors only the shape of the public dataset named in dataset.mirrors
